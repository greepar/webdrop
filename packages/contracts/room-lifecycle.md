# 房间离开、关闭与会话恢复契约

状态：基于 OpenAPI 0.5.0 的生命周期补充约定。本文件不新增路由、字段或角色，不代表本轮已验证所有后端实现；两端按下述验收项核对并补齐。正式请求/响应 schema 与逐接口错误以 `openapi.yaml` 为准。

## 操作与权限

“返回首页”（页面导航）、“离开房间”（撤销自身成员关系）和“关闭房间”（使房间整体失效）是三个不同操作。导航不隐含后两者。

| 操作 | 接口与成功结果 | 可观察行为 |
| --- | --- | --- |
| 返回首页、刷新、关闭标签页、暂时断网 | 不发送离房或关房请求 | 保留服务端成员关系；不转让 owner |
| 恢复会话 | `POST /api/v1/sessions`，有效 Cookie 返回200，新会话返回201 | 响应为 SessionCreated；完整成员关系另通过 GET session 获取；不能通过房间号或密码恢复旧 owner 身份 |
| 查询可恢复房间 | `GET /api/v1/session`，200 Session | 使用 `data.memberships` 中的 room 与 membership；只返回当前会话仍有效的成员关系，不是公开房间列表 |
| 进入已有成员房间 | `GET /api/v1/rooms/{roomId}`，200 RoomSnapshot | 重新验证权限，随后按 protocol.md 获取内容并建立 SSE；不重复创建成员或重新申请入房 |
| 普通成员主动离房 | `DELETE /api/v1/rooms/{roomId}/members/me`，204，无响应体 | 撤销自身房间权限；其它成员通过 `member.left` 更新成员列表；房间本身保留 |
| owner 主动离房 | 同上，409 `OWNER_MUST_CLOSE` | 不撤销 owner、不关闭房间；客户端需引导选择保留房间返回或显式关闭 |
| owner 关闭房间 | `DELETE /api/v1/rooms/{roomId}`，204，无响应体 | 撤销所有成员访问及关联公开分享，释放房间关联资源；向现有 SSE 发送 `room.closed` 后结束连接 |
| 普通成员关闭房间 | 同上，403 `OWNER_REQUIRED`（仍为有效成员时） | 不改变房间状态；未登录、无成员权限等错误仍按 OpenAPI |

离房/关房写请求携带 Cookie、允许的 Origin、X-CSRF-Token；不要求 PoW 或 Idempotency-Key。不添加“退出即关闭”的新隐式行为。

## 恢复、离线与清理

- 服务端会话是身份来源。客户端本地 roomId/房间号仅用于导航提示，不能授予访问或管理权限；管理能力按当前会话的 membership.role 判定。
- 已有有效成员恢复房间访问不重新验证房间密码、不重新审批；锁定不阻止已有有效成员恢复。主动离房后再加入需重新遵循当前密码、审批、PoW 与容量规则；被踢会话不能再次加入。
- owner 暂时离线不关闭房间、不自动移交权限。Cookie 丢失或会话失效后不提供匿名所有权找回；同房其它成员不自动成为 owner。
- 在线租约按 protocol.md 执行：房间资源请求/SSE 心跳刷新租约，90秒无活动离线；全员离线持续30分钟后由服务端自动关闭，清理任务及访问到期检查执行回收。客户端不自行宣布房间到期；`expiresAt` 不作为客户端推算全员离线时刻的依据。
- 首页的恢复入口不应仅为保持入口而持续订阅房间 SSE、轮询房间内容/成员/审批或发送房间心跳。页面离开后释放该页面的订阅和轮询；同会话其它仍打开的房间标签页可以继续活动，不能因此误判整个设备已离线。
- `GET /api/v1/session` 的 memberships 不得包含已关闭、已到期或当前会话已离开/被踢的房间。返回首页保留的有效关系可以占用成员名额，这是保留房间的语义，不等于前端残留的无效入口。
- 房间关闭、离房或踢人后，即使客户端持有旧快照、旧事件游标或成功幂等缓存，后续资源请求和 SSE 重连仍必须执行当前权限校验，不能恢复访问。

## 失败、并发与多标签页

- 204后才将显式离房/关房操作标记成功。网络超时或5xx不说明写入失败，也不说明成功：先重新读取会话成员关系和房间快照，再决定展示或重试，不无条件恢复旧界面。
- 401 `SESSION_REQUIRED`：停止旧会话请求，按会话协议恢复或建立会话，再读取 memberships；新会话不继承旧身份。
- 404 `NOT_FOUND`：不能继续访问该资源；刷新成员关系并移除已失效的恢复入口，不把404单独解释成“房主主动关闭”。网络错误、429和5xx不作为清除成员关系的依据；429遵循 Retry-After。
- 409 `OWNER_MUST_CLOSE`：保留原成员关系；403 `OWNER_REQUIRED`：停止管理操作并刷新权限。重复离房/关房不承诺再次返回204，按当前状态可能返回404；禁止扩大其它既有错误的语义。
- 本地标签页间可以广播“需重新验证状态”的通知，但服务端始终是事实来源。重新聚焦/恢复连接时重新校验，已离房/关房的标签页不能凭缓存复活成员关系。
- SSE断开不等于房间关闭：可能是正常120秒轮换、网络故障或撤权。收到 `room.closed` 可立即清理；未收到时按重连鉴权和快照校验处理，避免无限重连已失效房间。事件结构仍为业务信封，`room.closed` 的 data 为 `{id: roomId}`。
- 不在 beforeunload/unload/pagehide 中自动调用离房或关房请求。

## 与审批、密码的组合

密码与审批独立，具体顺序及错误遵循 room-password.md、room-approval.md。owner 离线时不自动批准或取消审批要求；有效 pending 申请继续等待并按原有效期过期。房间关闭后申请查询遵循原契约返回404；申请者不能继续轮询或把旧 approved 状态当作有效成员权限。

## 两端验收

1. owner 返回首页后房间保留，同会话再次打开恢复 owner；刷新不新增成员，不重新触发密码/审批。
2. 普通成员主动离房返回204，从 Session.memberships 移除，旧资源请求/SSE重连失去权限；不关闭其它成员的房间。
3. owner 离房返回409且状态不变；普通成员不能关闭房间；owner 关闭返回204，成员关系、分享链接及旧权限失效，现有连接收到关闭事件。
4. 暂时离线不转让房主；全员离线达到阈值后自动关闭，活跃的其它标签页不被错误回收。使用可控时钟验证边界，不让测试等待30分钟。
5. 离房、关房响应丢失、重复请求、多标签页、断线期间漏收关闭事件均能通过重新校验收敛；网络故障不误报成功、不清除有效入口。
6. 会话丢失不能靠密码或房间号获得旧 owner 权限；owner 离线时申请不绕过审批，房间关闭后申请不能继续授予权限。

具体按钮、确认框、侧栏入口、文案和动画由前端规范决定，本契约只定义操作语义与跨端状态。

## 后端核对修正（兼容0.5.0）

保留既有路由、字段、角色和错误语义。补齐最后在线成员离开时从离开时刻开始全员离线计时；到期清理不因随后404/401等业务失败回滚；现有SSE连接在关房时优先发送room.closed并结束，即使游标已落出保留范围。新连接仍按当前权限拒绝，不通过已关闭房间重放历史。

文件访问与内存预算在关房时失效，磁盘终态文件由既有15秒清理任务回收；已开始的下载可按protocol.md完成。POST sessions 保持正式OpenAPI的SessionCreated响应，GET session返回含memberships的Session。上述为既有行为纠错，无需客户端新增请求或字段。

现有成员（包括owner）读取单个审批状态同样刷新租约；尚未入房的申请者轮询不刷新房间租约，不能用等待申请阻止全员离线回收。后端已针对上述边界补充可控时钟、并发和恢复测试；浏览器页面事件行为仍由前端独立验收。
