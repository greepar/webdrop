# WebDrop 前端目标

范围以 `apps/web` 为主。技术栈为 React + TypeScript + Tailwind CSS；不修改后端内部实现。唯一跨端依据是 [API 契约](../../packages/contracts/README.md)、`openapi.yaml`（当前 0.3.0）、`protocol.md` 和 PoW 测试向量。

## 当前基线（2026-11-01）

前端已有业务页面，不再是纯技术 base。下列功能已有代码，但不代表完整验收通过：

- 极简首页、房间号输入、随机创建、指定号码创建、独立加入入口。
- 低饱和亮暗主题、手绘轮廓、响应式基础样式。
- 房间聊天、成员与管理入口、历史分页、上传队列、分享面板和分享页。
- Worker PoW、HTTP API 消费、SSE 订阅及重新同步入口。

本轮静态检查：`npm run check`、`npm run lint`、`npm run build:web` 通过。未重新进行浏览器视觉验收和真实服务联调；旧 mock 检查不作为真实功能完成证据。

## 设计方向与实施顺序

视觉方向：低饱和中性底色（暖灰/深灰），手绘只体现在细线、略不规则圆角与自绘图标；强调色只用于主要操作和焦点，不用大面积高饱和色。首页保持大图标、`WebDrop` 品牌字、房间号输入三件事，不加口号与功能卡片。房间页以内容流为主，输入区固定在底部，管理入口收进弹层。

实施顺序：契约与状态修复 → 业务交互补齐 → 视觉与响应式 → 动效与性能 → 真实服务与设备验收。每阶段只勾选有实际证据的条目。

## 固定产品与视觉要求

- 首页独立展示大图标、准确大小写的 `WebDrop` 品牌字和房间号输入区，不添加口号、功能介绍卡片或工作空间侧栏。
- 房间号保留前导零，支持粘贴和数字键盘，位数来自能力配置。输入框右侧依次是随机和加号按钮；随机直接创建，加号按输入号码创建，加入已有房间是独立动作。
- 低饱和中性色、简洁手绘线条、克制装饰和清晰层级；正文清楚易读，不能以低对比换取柔和感。
- 全页面、弹窗、菜单、PoW 和媒体预览共用语义主题；默认跟随系统，允许手动切换并持久化，首次加载避免闪烁。
- 文字、文件、图片和视频使用统一聊天内容流，显示发送者与时间，区分自己和他人。读历史时不强行滚动，新消息提示明确。
- 输入区保留换行与输入法行为；手机键盘出现后输入和发送仍可用。不禁止用户缩放。
- 动效自然、快速、可中断，优先 transform/opacity，尊重减少动态效果设置，包括程序触发的滚动。
- 权限、人数、文件限制、有效期与冷却以服务端配置和响应为准，不能通过隐藏按钮代替鉴权。
- mock 仅用于明确标识的开发或测试流程，不把模拟成功记为真实功能完成。

设计与审查使用 `design-taste-frontend`、`impeccable`、`emil-design-eng`、`animate`、`animation-performance`、`review-animations`、`humanizer-zh`；用户确认的极简首页与视觉约束优先。

## 房间密码与入房审批（0.4.0 / 0.5.0）

契约依据：`packages/contracts/room-password.md`、`room-approval.md`、`openapi.yaml` 0.5.0、`errors.md`。

| 契约要求 | UI 入口与状态 | API / 事件 |
| --- | --- | --- |
| 可选密码，1–72 UTF-8 字节，不 trim | 创建面板可选填；房主在“房间设置”设置/更换/取消 | `POST /rooms`、`PATCH /rooms/{id}` 的 `password` |
| 加入需密码，缺失或错误 403 | 加入失败后就地出现密码框，重新申请挑战与新幂等键 | `POST /rooms/join` 带 `password` |
| 审批开启时 202 + request | 首页切到“等待房主同意”，显示房间号与有效期，3 秒轮询、页面隐藏暂停 | `POST /rooms/join` → 202；`GET .../join-requests/{id}` |
| 房主审批 | “房间设置 → 入房申请”列表，同意/拒绝，显示待处理数 | `GET .../join-requests`、`approve`、`reject` |
| `hasPassword` / `approvalRequired` | 设置面板与创建选项；`room.updated` 刷新 | Room/RoomSnapshot 字段 |
| 状态冲突 | 409 `JOIN_REQUEST_STATE` 刷新、409 `ROOM_FULL` 保留申请、429 `JOIN_REQUEST_LIMIT`/`RATE_LIMITED` 按 `Retry-After` | `errors.md` |

实现要点：

- 密码只存在于提交表单的组件状态与请求体，不写 URL、localStorage、日志；`ROOM_PASSWORD_INVALID` 后不复用旧证明或旧幂等键。
- 202 不是入房成功：等待期间不请求快照、成员、内容或 SSE；批准后由状态轮询触发进入，访问权仍以房间 API 鉴权为准。
- 审批列表与申请状态均 3 秒轮询、页面隐藏暂停、429 按 `Retry-After` 退避；契约未新增申请类 SSE 事件。
- 申请者可取消等待（仅停止本地轮询）；拒绝/过期/404 回到表单并给出简短说明。
- 已有成员重连不要求密码；锁定优先于密码与审批（实测锁定房间不产生申请）。
